# قائمة الأمان قبل أي إطلاق (من المدربة)

**متى تُستخدم:** قبل إطلاق أي نسخة أو ميزة كبيرة، اقرأها وطبّقها بنداً بنداً، وسجّل النتيجة بدليل (أمر/ملف/اختبار) في `docs/security/AUDIT.md`.

> تطبيقي اللي برمجته على السريع بيتهكر.
>
> 1. طلّع كل الـ API keys من الفرونت إند
> 2. غيّر أي مفتاح لمس GitHub
> 3. فعّل row-level security على كل جدول
> 4. تحقق من الـ auth في كل API route، من جهة السيرفر
> 5. حط rate limit على تسجيل الدخول والتسجيل وأي شي يكلف فلوس
> 6. تحقق من كل input في السيرفر
> 7. لا SQL مبني بالسلاسل النصية، استخدم parameterized queries
> 8. اقفل CORS على دوميني أنا بس
> 9. خلي الكوكيز httpOnly وsecure وsameSite
> 10. شفّر الباسوردات بـ argon2 أو bcrypt
> 11. لا تثق أبدًا في user ID يجي من الكلاينت
> 12. أخفِ الـ stack traces في الإنتاج
> 13. افحص الـ dependencies عن ثغرات معروفة
> 14. حط security headers
> 15. حط حدود صرف على كل API مدفوع
> 16. ابحث عن كل ثغرة قبل ما يلقاها غيرك.

## طريقة الفحص في هذا المشروع
- المفاتيح: `grep -rn "process.env" src --include=*.tsx` في ملفات "use client"، وفحص تاريخ git عن أسرار.
- RLS: استعلام `pg_class.relrowsecurity` لكل جداول public، و«حالة الإعداد» في لوحة الإدارة تتأكد أن اتصال الموقع لا يتجاوز RLS.
- المسارات: كل ملف في `src/app/api/**/route.ts` وكل إجراء في `src/app/actions/*.ts` يبدأ بفحص الجلسة.
- SQL: لا `${...}` داخل نص استعلام إلا عبر `lit()`/`litList()` أو أسماء ثابتة.
- الاعتماديات: `npm audit --omit=dev`.
- الهيدرز: `curl -sI https://navcoaching.com/`.
